# Evidence, Provider and Admission Contract

## Offline corpus preparation

Importer accepts an operator-selected local source file and approved manifest, not arbitrary runtime URLs. Record source/edition notices, raw checksum, extraction version and code-point-normalized display text checksum. Parse full questions/articles and objection, sed contra, respondeo and reply sections; collective replies are first-class relationships. Unexpected heading/role patterns fail the import rather than silently losing article context. Require one main answer per article, valid objection/reply references and stable canonical locators. An explicit approved exception handles genuine source structure, never a heuristic relabeling of objections as conclusions.

Search normalization and bilingual aliases are derived artifacts. They may strip accents/case for matching but cannot change source quotation storage. Corpus output is private and immutable, <=8 MiB for the initial allowlist; every source article served is <=256 KiB. Rights manifest must be approved for intended serving jurisdictions before packaging public-service corpus data. Importing a local file is not rights approval.

## Retrieval and generation

1. Normalize the question for search only; retain its submitted language selection. Query reviewed Hungarian/English topic aliases plus lexical article/section terms. Deterministic ranks and a corpus version make fixtures reproducible. Thresholds are calibrated against the approved finite bilingual cases; below threshold abstains, not arbitrary low-confidence generation.
2. Select <=3 article packs. Each contains titles, canonical locator, exact relevant sections, main answer and applicable reply/objection context. If whole required context cannot fit the generation allocation, drop the article or abstain. Never truncate away the reply that reverses an objection. Main-answer and reply roles are enforced server-side, not inferred from provider prose.
3. Provider receives the question and labeled evidence as untrusted data beneath fixed instructions. It emits structured `claims[]`, evidence IDs/spans, `limitations[]`, and optional generated translations. At most six claims, twelve citations and three translations. It may abstain. No model-generated citation URL, edition metadata or original quotation is trusted or rendered.
4. Deterministically validate schema, IDs, exact span bounds/hash, article/section role, required context and any offered quote string against the bundle. A citation to an objection cannot support an attribution of Aquinas’s conclusion without explicit main-answer/reply grounding. Unsupported roles, changed source text, fabricated location or malformed schema cause abstention/failure without regeneration.
5. Invoke one separate verifier with the selected question, candidate claims/translations and all necessary source context. Its structured verdict includes each claim ID and `supported|unsupported|unknown`, role correctness, language and translation fidelity. It cannot invent replacement claims or broaden citations. Require one verdict for each supplied item. Any unsupported/unknown claim, misattribution, failed language/translation check or verifier failure withholds the whole candidate and yields a curated abstention/failure. No self-repair loop. A partial answer is permitted only when the original candidate itself explicitly limits scope and all its displayed claims pass.
6. Compose citation metadata and quotations from the source bundle, and label generated translations. Commit the verified result atomically with quota/cost settlement before sending it to the browser. No draft streaming. Semantic model verification remains fallible; approved human-reviewed bilingual cases are the release oracle, not an assertion of universal correctness.

Fixed labels for main answer, objection and reply are curated in hu/en. An objection quoted to explain the argument is visibly labeled and paired with Aquinas’s response. A faithful quotation in a misleading context fails semantic support even if every character matches.

## Provider transport

Candidate: OpenAI Responses API at a fixed trusted HTTPS endpoint on `api.openai.com:443`, POST `/v1/responses`; model and price manifest are server-controlled. Use native server fetch, redirect mode error, no arbitrary base URL, no tools, attachments, background execution, conversation continuation, provider search or SDK retry layer. Validate configured destinations at startup, reject private/link-local/loopback/metadata destinations, and use a reviewed DNS/address-pinning strategy or infrastructure egress allowlist to prevent DNS-rebinding bypass. Fake fixture transport is injected without changing production allowlists. No runtime source network requests exist.

Set `store=false`, `stream=false`, reasoning none, strict output schema and bounded output on every call. Reject refusal, incomplete status, missing/duplicate terminal content, unknown fields where schema disallows them, unexpected model identity, impossible usage or >1 MiB upstream body. Abort reading at limit, never buffer unbounded data. Scrub all provider errors to categories. No provider payload or HTTP headers enter logs. Redact database driver error parameters and disable request-body/SQL/SDK/APM capture for this route.

One logical operation may invoke generation once and verification once. Generation uses <=7,000 total input tokens and <=1,200 output tokens; verification <=5,000 input and <=300 output. Counts include developer/system instructions, schema and message wrappers. Combined input<=12,000, output<=1,500, including any reasoning/billable tokens under the reviewed pricing rules. The verifier must fit source context plus candidate prose; if it cannot, abstain without increasing its allocation. The launch tokenizer must be pinned and compatible with the selected model. Establish a conservative upper bound for serialized overhead; if current provider behavior cannot be bounded from reviewed evidence, activation fails.

Set a 60-second overall deadline from admission, with maximum 30-second generation and 20-second verification transport phases inside it; reserve time for local checks and final commit. Database lock/statement timeouts must fit remaining deadline. Return safe outcome within 65 seconds including sanitization. Local abort is not evidence that provider work stopped; retain uncertain reservations and capacity. No reconnect or new request may resume an uncertain dispatch. A future explicit reconciliation path may confirm usage using text-free provider records under separate authorization; it is not a hidden third provider generation call.

## Price manifest and invariant

Versioned reviewed manifest includes provider/model, tokenizer identifier, input/output and all applicable cache-write/regional rates, allowed request flags, maximum stage allocations, reviewedAt, expiresAt (<=24 hours), currency unit, and source links. Do not accept client rates or cached-token discounts as authority. Restrict any caching to the reviewed envelope; no repeated explicit cache breakpoints. All permitted billable categories must have a finite upper bound, otherwise disable provider activation.

Worst-case researched example: input rate $0.25/M, output $0.50/M, 10% regional uplift => two-call maximum 4,125,000 nano-USD. Real admission uses the active reviewed manifest and rounds each stage upward. Sum generation+verification maximum before reserving; all future stages are already covered. No monthly top-up or automatic model escalation.

Atomic invariant: `settledNanoUsd + outstandingReservedNanoUsd <= 10_000_000_000` per original UTC admission month. A pre-dispatch transaction records the intent and irreversible dispatch fence before network work. An ambiguous database commit requires primary recovery, not a repeated send. A confirmed actual cost moves reservation to settled exactly once; failed/unknown usage keeps full maximum, and proven unused second-stage capacity may be released. Duplicate/late worker settlement cannot refund twice. Model usage exceeding the reviewed bound halts new dispatch and records the discrepancy; it is a release-invariant failure, not something to hide by clipping recorded usage.

A dedicated feature key/project must be used only through this adapter, including live validation. Provider dashboards are advisory unless a real hard cap is verified. Correct admission math does not establish immunity to provider billing errors, unannounced price changes or database loss; these risks require operational guarantees, expiring configuration and reconciliation before any hard actual-spend claim.

## Admission and failure rules

Origin/input/network and token preflight precede paid dispatch. Local unsupported evidence may consume an answer slot but costs zero. Atomically reserve monthly money, daily answer slot, per-browser/global active capacity, dedupe ID and receipt storage. Separate calls to independent stores are forbidden for this decision. Existing Redis command budgets and Q&A dollar budget must never be substituted for one another.

Known provider refusal/failure consumes actual known provider cost but no completed-response daily slot. Candidate rejected for insufficient verified evidence can produce a completed abstention and consume one slot. Missing/malformed provider result is a failure rather than pretending to be a completed answer. Unknown outcome retains its daily slot and concurrency occupancy until reliable reconciliation. Stale worker leases release neither cost nor active paid concurrency. Halt globally before retention cleanup can erase identity needed to enforce unresolved per-browser concurrency.

## Threat boundaries

Questions and retrieved/provider text cannot alter fixed instructions, select endpoints, disclose credentials or request actions. Evidence is a data structure with explicit roles, never executable prompt text. No external tools exist to honor injected actions. Source links are local validated paths plus approved provenance links; browser rendering is text-only with existing CSP. Unit and browser cases must include hostile source text, quotation-like role labels embedded inside text, scripts, exfiltration links and credential sentinels. Never rely on a prompt sentence alone for security or cost enforcement.
